# Office Hours · c1_stitchgrid (ThreadGrid)

## Pain hypothesis (S3 输入)
绣友想把照片变成可绣的图样并在手机上跟踪进度;iOS 在位工具(Stitchly/Markup R-XP)在导入可靠性、维护与变现上集体失能,Pattern Keeper 缺席 iOS。

## Follow-up questions(≥2,含 narrow-wedge 必答两问)
1. **Top-N 在哪些时刻仍然辜负用户?** Stitchly 的 PDF/照片导入崩溃与"图样尺寸被压小"是评论区常驻;Markup R-XP 的符号识别不可信且 2024-04 后停更,订阅仍在收。它们辜负的不是边缘场景,正是核心回路(导入→信任→跟踪)。
2. **拿掉我们的 wedge 后会不会立刻塌成 clone?** 会塌的条件是:只做"照片转格子"。所以 wedge 必须是三段一体——可靠的创建(显式尺寸/色数控制、可编辑格子)+ 一等公民的进度标记(格子即数据,不依赖 PDF 符号识别)+ 可打印导出。三段同时在场时,iOS 上无直接对手。
3. **绣友会为移动端工具付费吗,还是被免费网页工具惯坏?** 评论区对"订阅 + 停更"的愤怒说明用户愿意为"被维护的工具"付钱、厌恶为"被遗弃的工具"持续付钱。消耗制导出点数(打印 PDF)比订阅更贴合"按幅付费"的手作节奏。
4. **进度标记在手机上会不会太小、不如纸?** 缩放 + 符号/颜色过滤 + "当前色"高亮是解法;v0 把最小可点格子尺寸写进设计约束。

## Revised pain
不是"没有工具",而是"iOS 上没有一个可信的图样工作室":导入不可靠、维护缺席、变现敌对,导致绣友退守网页工具 + 纸质打勾。

## Scenario
晚上沙发:拍一张宠物照 → 60 秒内得到 DMC 格点图 → 微调色数 → 接下来几周在绣制模式里逐格标记 → 完工导出打印图解存档。

## Status quo / cost
Stitch Fiddle(网页)+ 打印纸 + 铅笔打勾;每幅图 1–2 小时清色,进度全靠纸,换设备即丢。

## Narrowest wedge
本地零账号"照片→DMC 格点图→逐格进度→打印导出"一体;创建可靠 + 进度可信 + 按幅付费。

## v0 judgment
值得做:四 tab + 编辑器 + 导出,深度达标;PDF 图纸符号识别导入明确不进 v0(那是 Markup R-XP 的泥潭)。
